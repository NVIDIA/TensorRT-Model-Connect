This section defines how to interpret the documentation over time.

The site currently documents **Latest**, which tracks the current public
development branch. There is no version selector because the project has not
published a documentation snapshot for a tagged release yet. The first tagged
release should create the first immutable versioned snapshot; until then, the
site must not imply that unreleased APIs belong to a stable numbered release.

| Question | Page |
| --- | --- |
| Which artifact/software combinations are meaningful? | [Compatibility](compatibility.md) |
| Which boundaries are known today? | [Limitations / Known Issues](known-issues.md) |
| How do I diagnose a failure after first run? | [Troubleshooting](troubleshooting.md) |
| What has shipped? | [Release Notes](release-notes.md) |
| How do I move between released contracts? | [Migration Guide](migration-guide.md) |
| How will an interface be retired? | [Deprecation Policy](deprecation-policy.md) |

Support claims remain exact: model ID/revision, configuration, runtime path,
target, software cohort, and evidence level all matter.
