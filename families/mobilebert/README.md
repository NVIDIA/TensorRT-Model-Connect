# MobileBERT

`MobileBertForPreTraining` checkpoints (`model_type: mobilebert`), validated on
[`google/mobilebert-uncased@1f90a6c24c7879273a291d34a849033eba2dbc0f`](https://huggingface.co/google/mobilebert-uncased/tree/1f90a6c24c7879273a291d34a849033eba2dbc0f).

One fixed-length float32 engine carries both pretraining heads, and every bundle
serves both semantic Tasks; the build `task` only names the primary one:

| Task | Input | Output |
| --- | --- | --- |
| `masked_text_to_token_scores` (default) | text, framed `[CLS] text [SEP]`, or caller token ids taken as given | masked-LM logits of the `[MASK]` rows, or of every row when there is no `[MASK]` |
| `text_pair_to_pretraining_relation_scores` | two texts, framed `[CLS] A [SEP] B [SEP]`, segment 1 after the first `[SEP]` | the two next-sentence logits, labels `next`, `not_next` |

```bash
python -m tensorrt_model_connect build google/mobilebert-uncased \
  --revision 1f90a6c24c7879273a291d34a849033eba2dbc0f --max-sequence-length 128 \
  -o mobilebert.bundle
trtmc encode mobilebert.bundle --task masked_text_to_token_scores \
  --text "The capital of France is [MASK]."
trtmc encode mobilebert.bundle --task text_pair_to_pretraining_relation_scores \
  --text "The cat sat on the mat." --text-pair "Then it fell asleep."
```

## Graph

The family builds the published layout and refuses the other switches by name
(`config.py`): `normalization_type: no_norm` (every encoder "LayerNorm" is an
elementwise affine map without statistics; only the masked-LM head transform has a
real layer normalisation), `trigram_input` (each row's 128-wide token embedding is
concatenated with its right and left neighbours before the projection to 512),
query and key from one shared 128-wide bottleneck with the value read from the
512-wide stream, extra feed-forward blocks per layer, `relu`, and a pooled row
that is the first row as it is (`classifier_activation: false`).

Precision is float32 only. Without normalisation the last layer of the published
checkpoint leaves the stream near 6e7, beyond float16, and the next-sentence
logits it feeds are near 2.7e8 with a gap of about 1e4, which bfloat16 cannot
resolve. TF32 is disabled in the builder for the same reason.

Inputs longer than the engine window are refused, not truncated.

The next-sentence head of the published checkpoint does not separate related
from unrelated pairs at its decision boundary: the transformers reference scores
`next` for all 33 pairs tried (related, shuffled, unrelated and swapped), with a
larger margin for real continuations (median 3.0e4) than for shuffled (2.0e4) or
unrelated pairs (1.2e4), and this family reproduces those logits. The Task
returns them as the checkpoint computes them; parity with the reference is what
is validated, not discrimination.

## Tokenizer

The native WordPiece tokenizer reads the bundle's `tokenizer.json` (the
checkpoint's own: uncased `BertNormalizer`, `BertPreTokenizer`, WordPiece).
Normalisation and word splitting use `runtime/unicode_tables.h`, generated by
`tests/unicode_tables.py` from the reference library pinned in `requirements.txt`
(`tokenizers` 0.22.2), one code point at a time over the whole code space; the
reference normaliser works character by character. Hangul syllables decompose
algorithmically. `tests/test_unicode_tables.py` regenerates the file and requires
it to be identical.

The one string-level step of the reference is canonical reordering of combining
marks. It can only change the output through marks that survive accent stripping
with a nonzero combining class (`kReorderable`); a word holding one is a single
`[UNK]` whatever the order when no vocabulary token contains such a mark. The
builder and the runtime therefore refuse a vocabulary that contains one; the
published vocabulary contains none. Text that is not well-formed UTF-8 is refused.

The tables are derived from the behaviour of `tokenizers` 0.22.2, which reflects
the Unicode Character Database. The Unicode notice is in `UNICODE_LICENSE.txt`,
also installed with native builds under `share/trtmc/families/mobilebert`.

transformers 5.2.0's `AutoTokenizer` is not a reference for this checkpoint: the
repository has no `tokenizer_config.json`, and transformers then builds a
`BertTokenizer` with `do_lower_case=False` that ignores the file's lowercasing
normaliser ("The" becomes `[UNK]`). The tests take reference ids from
`tokenizer.json` through the `tokenizers` library.
