# OpenAI GPT

`families/openai_gpt` builds `OpenAIGPTLMHeadModel` checkpoints (`model_type` `openai-gpt`, the original GPT) into
one TensorRT engine and serves them through the `text_continuation` Task. The validated checkpoint is
[`openai-community/openai-gpt`](https://huggingface.co/openai-community/openai-gpt) at revision
`1e0d4f3028acbffb47fe933cea64619c5ec1a002`: 116.5 M parameters, 12 post-norm layers, 512 learned positions, float32.

## Build

```bash
trtmc build openai-community/openai-gpt --revision 1e0d4f3028acbffb47fe933cea64619c5ec1a002 \
  --precision fp32 --max-sequence-length 512 -o openai-gpt.bundle
```

The checkpoint is float32 and `fp32` is the only precision built (TF32 off). One engine has a prefill profile (a
whole prefix in one launch) and a one-token decode profile over the same weights; both update one KV cache of
`max_sequence_length` rows in place (at most `n_positions`, the default). The LM head reuses the token embedding,
as the checkpoint ties them. `h.<i>.attn.bias` in the checkpoint is a stored copy of the causal mask, which
transformers recomputes; it is not read.

## Run

```bash
trtmc run openai-gpt.bundle --prompt "The old harbor was quiet at dawn, and" \
  --max-new-tokens 32
```

Config fields: `max_new_tokens` (default 128), `temperature`, `top_k`, `top_p`, `min_p`, `seed`; the default is
greedy decoding, as `generate()` of this checkpoint. The checkpoint declares no EOS token, so generation produces
`max_new_tokens` tokens. A prefix of `n` tokens with `m` new tokens needs `n + m - 1` cache rows; a request that does
not fit is refused, not truncated. A prefix is text or token IDs; it may not be empty (there is no start token).

## Tokenizer

The native tokenizer reads the bundle's `tokenizer.json` (the checkpoint's own: uncased `BertNormalizer`,
`BertPreTokenizer`, BPE with the `</w>` end-of-word suffix and one `<unk>` per unknown character, `BPEDecoder`) and
is compared id for id with the `tokenizers` library on the same file. Normalisation and word splitting use
`runtime/unicode_tables.h`, generated by `tests/unicode_tables.py` from the reference library pinned in
`requirements.txt` (`tokenizers` 0.22.2), one code point at a time; Hangul syllables decompose algorithmically, and
`tests/test_unicode_tables.py` regenerates the file and requires it to be identical. The one string-level step of the
reference, canonical reordering of combining marks, cannot change the ids while no vocabulary token holds a mark it
could move, so the builder and the runtime refuse a vocabulary that holds one; the published one holds none. Text
that is not well-formed UTF-8 is refused. Decoding skips special tokens, as the text-generation pipeline does.

transformers 5.2.0's `OpenAIGPTTokenizer` does not read this normaliser: it rebuilds the tokenizer with `NFD`,
`Lowercase` and `StripAccents`, which keeps control characters, does not separate CJK ideographs from neighbouring
letters and also removes spacing and enclosing combining marks. On text without those characters both give the same
ids (`tests/test_tokenizer_parity.py` checks this and the E2E prompts). The tables derive from the Unicode Character
Database; the Unicode notice is in `UNICODE_LICENSE.txt`, and the provenance of the reimplemented Transformers and
Tokenizers procedures and the checkpoint's MIT license are in `NOTICE`; both are installed under
`share/trtmc/families/openai_gpt`.

## Validation

- `tests/test_e2e.py`: build, CLI and direct C / C++ SDK calls on the checkpoint. Greedy cases must give the token IDs
  of greedy decoding with the float32 transformers model, including a prefix that fills all 512 cache rows; the
  seeded sampling case must repeat for its seed, change with it, and keep only tokens that transformers' temperature,
  top-k and top-p processors allow.

  The greedy reference runs one forward pass of the whole sequence per token, not `generate()`: this model has no KV
  cache, but transformers 5.2.0 `generate()` passes it, from its second step on, the cached-decoding `position_ids`
  of the newest token together with the whole sequence, and the model then adds that one position embedding to every
  token (its continuations degrade into repetitions such as "freyja freyja").
- `tests/test_engine.py`: the engine, launch by launch through its cache (initially NaN), against the float32
  transformers logits of every position up to 512; a launch with positions shifted by one must fail the same bound.
- `tests/test_tokenizer_parity.py`, `tests/cpp/test_openai_gpt_text_runtime.cpp`: tokenizer and sampler; the native
  tokenizer refuses every `tokenizer.json` that the builder's contract (`tokenizer_contract.py`) refuses.
- `tests/test_builder.py`: configuration, checkpoint reader and build options without a GPU.
